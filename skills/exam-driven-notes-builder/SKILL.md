# 凝练教材制作

把课程资料转成可理解、可复习、可用于答题的分章 Markdown 教材。保留名词先行、主题内机制与对比、章末知识框架的阅读体验。凝练指减少重复和冗余，不是减少知识覆盖。

## 读取入口

- 先读 [references/formatting.md](references/formatting.md)，它负责格式及定义规则。
- 生物课程再读 [references/biology.md](references/biology.md)。当前提供生物模板；其他学科沿用用户提供的对应模板，不套用生物结构。
- 每次任务使用 [references/workflow.md](references/workflow.md) 的来源登记、覆盖表和进度记录。
- 需要子代理时使用 [references/chapter-delegation.md](references/chapter-delegation.md)；没有子代理工具时串行执行同一章级任务。
- 产物将用于用户的学习系统时，读取 [references/learning-handoff.md](references/learning-handoff.md)，核对分区、单元、导入入口与已有学习进度。
- 新章以 [assets/biology-chapter.md](assets/biology-chapter.md) 为结构起点，按内容删除不适用的标签和占位说明。
- 如需本地 HTML 样式预览，可使用 [assets/notes-preview.css](assets/notes-preview.css)；它提供参考成品的灰色注释、公式框和表格样式，正文不依赖此样式表。

参考资料相对本文件定位；辅助工具位于本 skill 的 `scripts/`。课程输入、缓存和输出使用用户指定的工作目录，不把安装目录当作课程工作目录，也不写死盘符。

## 来源与范围

**稳定基础输入：上课 PPT + 指定课本。** 老师发的试卷、往年卷、老师重点清单及用户提供的辅导书均为可选增强资料。缺少试卷或辅导书时直接跳过相关阶段，不能卡住流程，也不能伪造考题照应。

| 资料 | 用途 | 不应推导出的结论 |
| --- | --- | --- |
| 上课 PPT、老师明确重点 | 决定课程主线、讲授范围和重点深度 | PPT 每一页都必考 |
| 老师试卷、往年卷（有才用） | 提炼实际考查任务，强化对应主题 | 没出现过就不考；重复上传算多次考查 |
| 用户提供的辅导书（有才用） | 补机制、对比、例子和答题组织 | 辅导书考研真题就是本课程真题 |
| 指定课本 | 全章兜底、核准术语、补分类及知识联系 | 课本目录可替代老师讲授的课程安排 |

制作顺序：**PPT + 可用试卷建立粗版 → 可用辅导书补强 → 课本全面核对与扩展 → 本章审校定稿。** 课本目录可在建框架时先查，概念疑问可提前查证；不要为了流程顺序让粗版写入未经证实的答案。

课程章节优先沿用用户或老师明确的课程大纲、已有课程映射；其次按 PPT 课程顺序并建立课本映射，无法确定时才用课本目录。同一课程可合并、拆分课本章节，不把课次当作输出章。章内按知识依赖及主题聚合组织，不按题目逐条拼接。明确排除的范围记入覆盖表；未明确排除的课本重要内容纳入本章，弱相关内容简写或建立跨章指向。

课件可能是课次文件夹中的截图和图片式 PDF；先看内容与现有缓存，不只搜索 `.pptx/.ppt`。`OCR/`、`多模态/` 可能保存的是待识别图片，目录名不代表已得到文本。截图、PDF 和路线记录可能对应同一页，应按课次与页序去重，排除考勤界面等非教学截图。

区分两种优先级：PPT/试卷优先决定**学什么、哪里展开**；事实准确性仍需原始资料核对。老师资料与课本冲突时保留出处、注明适用口径，不能以考试优先为由复制明显错误。不能解决的关键矛盾单列待核实，不能当作已审校。

## 章级闭环

1. **盘点与续做**：读取资料登记和 `_进度.md`，核对文件实际存在、当前章节及用户范围。默认逐章推进，不重复询问已经明确的偏好。只有缺失的必要信息影响范围或准确性时才提问，同时继续不受影响的部分。
2. **建章节包**：记录本章 PPT 页/幻灯片、课本章节/页码、可用题目与辅导书页码，建立主题覆盖表及读取清单。先完整读取 PPT 与可用试卷；辅导书和课本正文在各自补强阶段通读。大章按主题分段，记录未读区间，不能以搜索命中代替通读。
3. **粗版**：以 PPT 主线和可用试卷考点组织主题。写出已核实的概念、过程、图示含义与考查任务；缺口留在缓存覆盖表，不在正文堆积待填占位。粗版保存到缓存，不能计作成品。
4. **辅导书补强**：有资料才做；把有用的机制解释、对比和答题逻辑并入相应主题。删除重复，核对答案及适用条件。不扩大为另一套考试范围。
5. **课本兜底**：逐节对照目录与正文，补遗漏概念、分类分支、机制条件、例外、实验依据和跨章联系。允许回到已经写过的主题补充，但最终同一主题连续呈现。核心术语及数值回到原始页核准。
6. **审校**：同时检查来源覆盖、科学表达与 Markdown 格式。每个 PPT 实质要点、每个可用题目子问、课本每节重要内容都有正文锚点或明确排除理由；无法读取的内容必须显式记录。机械格式检查通过不能替代内容审校。
7. **保存与推进**：本章通过后保存 `输出/[课程名]/第N章_章节名.md`，更新进度及覆盖表，并简要报告完成范围与残留疑问。用户要求整门课时自动继续下一章；只要求一章时完成该章即可，不强制询问下一章。
8. **合并与交接**：全部约定章节审校通过后核对清单，按章号合并并检查总文档。用于学习系统时，另核对实际解析出的章、单元、名词与习题，并写交接记录；部分章成品不直接覆盖既有整门课程。制作完成和学习系统导入完成分开报告，实际导入按用户的明确请求执行。

## 稳定输出约束

- 不给术语数量、字数或对比维度设配额；按资料及学习需要决定。
- 不生成记忆口诀、押韵口号或用类似记忆提示替代；章末保留知识树、易错点和跨章联系。
- 核心内容讲到能解释、比较和答题；扩展内容与主题直接相关，注明“理解延伸”，不冒充必考重点。
- 第一部分给核心定义与必要辨析；第二部分首次展开该术语时包含同一定义句，详细机制放在第二部分，减少整段重复。
- 第一部分会被学习端切成待审闪卡，第二部分是课堂事实材料。当前课堂通常只读当前单元，不依赖第一、第三部分补齐必要定义、机制或条件；跨章联系所需的当前前提也要写进该单元。
- 原文定义不存在时允许基于资料归纳，在缓存的定义来源记录和交接清单注明“据资料归纳”；不能伪称逐字原文。OCR 疑点核对原图。
- 定义来源、页号、覆盖状态等内部记录放缓存，不以“定义来源／资料依据”标签写进第一、第二部分。保留真实考题照应作学生复习标注，学习端会从讲课材料和名词卡中过滤它。
- 第二部分直接以 `### （一）大主题` 开始，主题内用 `####`、标签和列表。不要在第一主题前堆说明形成额外“引入”单元；第一部分内部不放容易被误认成新名词的数字编号步骤。
- 题目只增强重点，不筛掉未被题目覆盖的课本知识。题目原文存在才写考题照应，定位到实际能回答它的主题；上位概念的近似匹配不算覆盖完成。
- 树状图和多行流程放在 `text` 围栏中，公式优先用独立等宽文本并解释变量及条件；表格优先窄表。遵循普通 Markdown 渲染，不依赖特定插件。
- 不改用户已确认的标题与顺序。新增资料使内容失效时标记“待复核”，只补受影响的章；已确认原文也可经证据校正并记录原因。
- 各章唯一成品名；粗版、覆盖表、来源记录放缓存。默认保存文件并更新进度，提交 Git 依用户要求，不把提交作为制作完成的前提。

## 工具与完成条件

辅助工具使用本 skill 的 `scripts/tool.py`，内容提炼由调用 skill 的 AI 完成，不需要独立的 API 配置或本地大语言模型。选择用户现有、具备所需依赖的 Python 环境；依赖说明见 `scripts/requirements*.txt`，不自动安装整套工具链。OCR 先验证环境，GPU 可用才启用，否则 CPU；旧 `.ppt/.doc` 的转换要求按实际工具确认。

在课程工作目录执行，`<skill_dir>` 替换为本 skill 的实际安装路径：

```text
python "<skill_dir>/scripts/tool.py" lint-notes "输出/[课程名]/第N章_章节名.md"
python "<skill_dir>/scripts/tool.py" merge "输出/[课程名]"
```

提取方法见 `scripts/tool.py --help` 与 [references/workflow.md](references/workflow.md)。原始文件、原始提取缓存和来源页号只读保留，清理结果另存。纯文字提取无法还原的图、公式和表格应查看原页，不能视为没有知识内容。

本 skill 制作完整凝练教材。仅根据课堂录音筛选老师强调内容的短提纲是另一种产物，不套用本 skill 的全面扩展或四分区验收。

**本章完成**意味着：覆盖表逐项核对；没有未解决的关键资料缺口或科学矛盾；定义与机制、对比和联系有出处；格式错误清零；实际渲染可用时检查本章标题、表格、公式与知识树。无法实际预览时报告“格式检查通过，未实际预览”，不声称已验证视觉效果。
